Chapter I

Dependencies

✦

Every dependency you import is a tax you pay forever, in builds, in scans, and in the shapes it forces on your code.

Seven direct dependencies sounded modest, but they dragged in a transitive tree with sonic, quic-go, protobuf, json-iterator, two YAML parsers, and a mock generator. A service whose job was polling Windows machines over WinRM was compiling a QUIC stack because the HTTP router had an HTTP/3 client somewhere in its graph. Each build paid for all of it, each vulnerability scan re-read all of it.

The routergo.mod
Before 
require github.com/gin-gonic/gin v1.11.0
require github.com/spf13/viper v1.21.0
require github.com/firdasafridi/gocrypt v1.1.0

// indirects: bytedance/sonic, quic-go/quic-go,
//            google.golang.org/protobuf, json-iterator/go
After 
require github.com/golang-jwt/jwt/v4
require github.com/jmoiron/sqlx
require github.com/jackc/pgx/v5

The before state shipped a JSON fast-path, a QUIC implementation, and a protobuf runtime to serve a handful of REST endpoints. The after keeps only libraries that do something the standard library cannot, and each is earned by a real call site.

Encryptionpkg/api/encryption.go
Before 
aesOpt, err := gocrypt.NewAESOpt(secretKey)
gc := gocrypt.New(opt)
err = gc.Encrypt(&entity)
// Special handling for json.RawMessage because gocrypt might have skipped it
// We'll use reflection to find json.RawMessage fields with gocrypt tag
if err := handleRawMessageFields(&entity, secretKey, true); err != nil { ... }
After 
func encryptString(aead cipher.AEAD, plain string) (string, error) {
    nonce := make([]byte, aead.NonceSize())
    if _, err := io.ReadFull(rand.Reader, nonce); err != nil { return "", err }
    ciphertext := aead.Seal(nonce, nonce, []byte(plain), nil)
    return hex.EncodeToString(ciphertext), nil
}

The old code was bad not because it was insecure, but because you could not see whether it was. The new code names every step of the cipher, enforces the key length at the boundary, and keeps the exact same wire format, so stored data decrypts with zero migration.

Configpkg/config/config.go
Before 
v := viper.New()
v.SetDefault("DB_HOST", "localhost")
...
v.AutomaticEnv()
v.Unmarshal(&config)
After 
func env(key, def string) string {
    if v := os.Getenv(key); v != "" { return v }
    return def
}

Viper existed to merge a yaml file with environment variables, yet secrets were only ever supposed to come from the environment, so the yaml file held little viper was actually needed for. The after keeps every default in one readable place, and seven pool tuning knobs collapse to three because three separately tuned pools had never been validated.

RememberBefore you import a library, ask whether the standard library already pays that bill. A dependency is a promise to carry its API, its bugs, and its transitive tree forever.

Chapter II

Failure & Errors

✦

Correctness under failure is a feature you ship before the failure arrives.

The API talked to the rest of the system over request-reply channels, and every handler trusted that conversation to end. A handler built a reply channel, pushed a request into the service's inbox, then parked with nothing else happening. If the service was down or wedged, the handler blocked forever: no timeout, no cancellation, no response, and a goroutine pinned for the life of the process.

The unbounded waitpkg/api/routes.go
Before 
replyCh := make(chan models.Response, 1)
reqCh <- models.Request{Operation: models.OpList, ..., ReplyCh: replyCh}
resp := <-replyCh              // blocks forever if the service is gone
After 
select {
case reqCh <- req:
case <-ctx.Done():
    return models.Response{}, ctx.Err()
case <-time.After(rpcTimeout):
    return models.Response{}, errServiceUnavailable
}
select {
case resp := <-req.ReplyCh:
    return resp, nil
case <-ctx.Done():
    return models.Response{}, ctx.Err()
case <-time.After(rpcTimeout):
    return models.Response{}, errServiceUnavailable
}

The before version had an unbounded wait, so a dead service turned a health check into a goroutine leak. The after bounds the wait at every hop, honors client disconnects via ctx.Done(), and keeps the reply channel buffered so the service side never blocks on a handler that already gave up.

Honest errorspkg/api/routes.go
Before 
if resp.Error != nil {
    respondError(c, http.StatusInternalServerError, resp.Error.Error())
    return
}
After 
code, msg := classifyError(err)
respondError(w, code, msg)
// sql.ErrNoRows → 404   duplicate key → 409
// foreign key (23503) → 409   validation → 400
// everything else → bare "internal server error"

Sending resp.Error.Error() to the client handed strangers the inside of your database layer and made every failure indistinguishable. The after logs the full error server-side and forwards only a classified, client-safe message.

Validationpkg/models/models.go → pkg/Services/persistence/entityService.go
Before 
Port int `db:"port" json:"port" binding:"omitempty,min=1,max=65535"`
// only gin honors these tags; any other transport gets zero validation
After 
func validateDeviceFields(device *models.Device) error {
    if device.Port != 0 && (device.Port < 1 || device.Port > 65535) {
        return fmt.Errorf("port must be between 1 and 65535")
    }
    if device.IPAddress != "" && net.ParseIP(device.IPAddress) == nil {
        return fmt.Errorf("ip_address must be a valid IP address")
    }
    ...
}

Tags in the model only worked inside gin, so validation was a transport accident. As service functions, the same rules run no matter how a request arrives, and their error strings are exactly the phrases classifyError recognizes, so the two halves agree on what a 400 looks like.

Startupcmd/app/main.go
Before 
if err := conf.ValidateSecrets(); err != nil {
    slog.Warn("Security validation warning", "error", err)
}
// server gladly serves JWTs and encryption keys over plain HTTP in prod
After 
if err := conf.ValidateSecrets(); err != nil {
    if os.Getenv("APP_ENV") == "production" {
        slog.Error("Refusing to start with insecure secrets", "error", err)
        os.Exit(1)
    }
}
if os.Getenv("APP_ENV") == "production" && (conf.TLSCertFile == "" || conf.TLSKeyFile == "") {
    os.Exit(1) // never serve the management API over plain HTTP

A process that refuses to boot unsafe is safer than one that runs with a warning. The duplicated TLS and plain-HTTP branches also collapsed into one server with explicit ReadHeaderTimeout and WriteTimeout, so slow clients cannot hold connections open.

RememberAssume every partner in the system can fail, and make each failure bounded, honest, and local. A timeout beats a wedged goroutine, a 404 beats a raw driver string, and a process that refuses to boot unsafe beats one that runs with a warning.

Chapter III

Observability

✦

An event-driven service is a black box until every hop carries its trace; the edges are the diagram.

NMS is a fan-out of goroutines joined by channels. A discovery request lands in the API layer, gets handed to EntityService, hops to the Scheduler, crosses into the Poller, drops into the plugin worker pool, and eventually writes through MetricsService into PostgreSQL. Every hop is a select on a channel, and every hop was a place where the story could die silently.

The message carries the tracepkg/models/event.go
Before 
type Event struct {
    Type    EventType   `json:"type"`
    Payload interface{} `json:"payload"`
}
After 
type Event struct {
    Type    EventType   `json:"type"`
    Payload interface{} `json:"payload"`
    TraceID string `json:"trace_id,omitempty"`
    SpanID  string `json:"span_id,omitempty"`
}

The producer stamps the message with StampEvent; the consumer rebuilds a real parent at the point of consumption. W3C trace and span ids ride the message itself, so child spans get genuine parents across goroutine boundaries.

Late children get mergedpkg/tracex/store.go
Before 
if _, ok := e.pending[traceID]; !ok {
    e.order = append(e.order, traceID)
}
e.pending[traceID] = append(e.pending[traceID], sp)
// a late child waits for a root that will never come, then is evicted unseen
After 
// Skip duplicates (retried exports or double-finalized spans).
for _, existing := range t.Spans {
    if existing.SpanID == cp.SpanID { return true }
}
t.Spans = append(t.Spans, cp)
t.SpanCount = len(t.Spans)
if t.EndedAt.Before(cp.EndedAt) { t.EndedAt = cp.EndedAt }

Async continuations end after the HTTP root, so they reach the exporter after the trace was finalized. Before, a waterfall that ended at the API layer showed a request that supposedly did nothing. After, late spans merge into the stored trace with span-ID dedupe, and the end time and component list are recomputed from the merged set.

The diagram is the contractpkg/tracex/topology.go
Before 
{ID: "discovery", Label: "DiscoveryService", Type: "service"},
{From: "discovery", To: "pluginpool", Label: "jobs"},
// nine nodes, the discovery pool missing, labels that no longer match
After 
{ID: "discoverypool", Label: "DiscoveryWorkerPool", Type: "service"},
{From: "discovery", To: "discoverypool", Label: "Jobs"},
// exact ten-node, fourteen-edge replica of ARCHITECTURE.md;
// isNodeID enforces only these ids may appear in a trace

The dashboard and the architecture document disagreed, and a viewer could not tell which one was stale. Now the diagram and the telemetry share one contract, so a trace that visits a node not on the map is a bug you can see, not a mystery.

RememberInstrument the hop, not just the node. In an event-driven service the edges are where the work happens and where it disappears. The trace only becomes useful when the message itself is the carrier, late children still get merged, and the graph you draw is the same contract the code enforces.

Chapter IV

The Developer Window

✦

A developer who can see the system live works ten times faster; build the window, but never let it leak secrets.

Real OTel spans already crossed every service boundary, but with no collector or UI they were invisible. What was missing was the window itself: a dashboard that turns the span stream into something you can click, plus the discipline to keep that window from showing secrets.

Wrap the outermost handlercmd/app/main.go
Before 
var h http.Handler = mux
h = api.SecurityHeaders()(h)
h = api.MaxBodyBytes(1 << 20)(h)
return h
After 
return api.TraceMiddleware()(root)
// auth middleware sits INSIDE the mux, so a failed login, a 404,
// or a 500 also gets a root span

In the before world, the failures you most wanted to understand were exactly the traces you could not see. Wrapping the root gives every request, including ones that die at the door, a root span.

Capture the body, restore it, mask itpkg/api/middleware.go
Before 
http.MaxBytesReader(w, r.Body, limit) // reject, but never see why
After 
if buf, err := io.ReadAll(io.LimitReader(r.Body, maxTraceRequestBody+1)); err == nil {
    r.Body = io.NopCloser(bytes.NewReader(buf))
    body := buf
    if len(body) > maxTraceRequestBody { body = body[:maxTraceRequestBody] }
    span.AddEvent("request.body", tracex.BodyEvent("request.body", tracex.MaskJSON(body)))
}

Read limit+1, not limit. Cap at exactly the limit and an oversized body comes back restored and truncated, sails past MaxBytesReader, and the API silently accepts bodies it used to reject. One extra byte preserves the rejection semantics. MaskJSON redacts payload, password, secret, token, authorization, matched case-insensitively, so the raw bytes never reach the span event.

Don't mutate what you re-renderweb/traces.js
Before 
var order = flattenTree(spans);   // stamps _children/_depth/_t0 onto the span
// re-rendered on every poll: 5 spans grow to 10, then 20, then 40 rows
After 
var copies = spans.map(function (s) {
    return Object.assign({}, s, { events: s.events, attributes: s.attributes });
});
var order = flattenTree(copies);

The cached trace is re-rendered on every poll, so mutating it in place compounds the tree on each render. Copy before you stamp.

SVG needs its namespaceweb/app.js
Before 
var node = document.createElement(tag);
// browser treats SVG tags as HTML and lowercases viewBox → viewbox:
// the canvas draws nothing, only text
After 
var node = SVG_TAGS[tag]
    ? document.createElementNS(SVG_NS, tag)
    : document.createElement(tag);

Case-sensitive SVG attributes (viewBox, markerWidth, textAnchor) survive only when the element is created in the SVG namespace. Two-line bugs like this cost hours of staring at a blank screen.

RememberInstrumentation is worthless until someone can look at it. Build the window early, let it show failures as well as successes, and redact secrets at capture time, never at display time: the capture layer is the only place masking cannot be forgotten.

Chapter V

Documentation

✦

Documentation is not a chore. It is the interface between humans, machines, and the agents you delegate to.

The system worked, but it worked in private. Nothing told a newcomer where the story lived. Issues existed only as a fact in the maintainer's head, the triage vocabulary was unwritten, and the component topology existed once in ARCHITECTURE.md, unlinked from the README that everyone actually opens.

A repo that tells its storyAGENTS.md
Before 
No AGENTS.md existed; a joining agent guessed conventions from scratch.
After 
# NMS

Network Monitoring System (NMS) - Lite. Go backend for discovery, monitoring, and
metric collection over WinRM. See `ARCHITECTURE.md` for the component topology.

## Agent skills
### Issue tracker
Issues and PRDs live as GitHub issues in `PremModhaOfficial/nms` via the `gh` CLI.
See `docs/agents/issue-tracker.md`.
### Triage labels
Default labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.
### Domain docs
Single-context repo. `CONTEXT.md` + `docs/adr/` at the repo root.

AGENTS.md does not repeat the story, it points to where each part lives. The whole contract fits on one screen, and everything deeper has a link.

One picture, three representationsREADME.md
Before 
A lightweight, extensible network monitoring system for discovery, monitoring,
and metric collection.
After 
graph TD
    API[API Layer] -->|Request/Reply| ES[EntityService]
    ES -->|sqlx| DB[(PostgreSQL)]

The same graph sits in ARCHITECTURE.md, and docs/dev-dashboard.md turns it into instrumentation with span names that match the arrows. One picture, three representations, all agreeing; a reader never reconciles contradictions.

RememberA repo whose story is written down can delegate work without re-explaining itself. Documentation pays compound interest: every issue filed, every agent run, and every future session starts from the same shared picture instead of a private scramble for context.

Epilogue

The Principles

✦

The index of wisdom this book exists to preserve.

  1. Every dependency is a tax paid forever; import only what the standard library cannot provide, and let each library earn its place by a real call site.
  2. Assume every partner in the system can fail, and make each failure bounded, honest, and local — a timeout beats a wedged goroutine.
  3. Validation belongs at the service boundary, where it survives any transport and agrees with the error classifier.
  4. A process that refuses to boot unsafe is safer than one that runs with a warning.
  5. Instrument the hop, not just the node; in event-driven systems the edges are where the work happens and where it disappears.
  6. Trace context must ride the message itself, and late children must still be merged, or the waterfall lies at both ends.
  7. The diagram you draw and the contract the code enforces must be the same graph, or nobody can tell which one is stale.
  8. Instrumentation is worthless until someone can look at it; build the window early, and let it show failures as well as successes.
  9. Redact secrets at capture time, never at display time; the capture layer is the only place masking cannot be forgotten.
  10. A repo whose story is written down delegates work without re-explaining itself — documentation pays compound interest.
